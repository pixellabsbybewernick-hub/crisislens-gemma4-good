# Data strategy for CrisisLens

The Gemma 4 Good Hackathon data tab states that this hackathon has **no provided dataset**. CrisisLens is therefore designed as a product prototype rather than a leaderboard model.

## What is included here

- `demo_scenarios.jsonl` — synthetic but realistic crisis-report scenarios for repeatable demos.
- `field_notes.csv` — batch-triage examples used by the Streamlit coordinator view.
- `sample_reports/` — example outputs generated by the app workflow.

## Why synthetic demo data is appropriate

Crisis reporting can include sensitive location, health, and identity information. For the hackathon demo, CrisisLens avoids using real victim data. The synthetic scenarios are deliberately built around common disaster-response patterns:

- blocked access route
- clean-water shortage
- shelter pressure
- landslide road obstruction
- wildfire smoke / evacuation support
- medical supply gap
- school infrastructure damage
- multilingual field notes

## How judges can test it

1. Run the Streamlit app.
2. Select any built-in sample scenario or upload a custom image.
3. Enter a field note.
4. Generate the report.
5. Inspect the JSON, routing output, SMS/radio summary, and uncertainty fields.

## What not to claim

Do not claim this is trained on a private disaster dataset. It is a local-first Gemma 4 workflow prototype that demonstrates a realistic operational pattern.
