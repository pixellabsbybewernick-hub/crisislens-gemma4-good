# Prize strategy

## Hard truth

No project can guarantee a prize. The best strategy is to maximize eligibility across multiple tracks and make the judging value obvious within the first minute of the video.

## Best prize targets

### 1. Global Resilience — primary target

CrisisLens is strongest here. It directly addresses disaster response, blocked roads, floods, landslides, shelter overflow, clean-water shortages, and low-connectivity coordination.

### 2. Ollama / Local Ops — technical target

If the video clearly shows Gemma 4 running through Ollama locally, this becomes a credible special-track submission. The app already supports this.

### 3. Safety & Trust — secondary impact target

The visible safety layer is important: uncertainty, missing info, no diagnoses, no identity recognition, deterministic routing, human gate.

### 4. Main Track — stretch target

For Main Track, the decisive factor is the video/story. The code alone is not enough. The judges must feel that this is a real product prototype, not a demo script.

## What would hurt the score

- Generic chatbot framing.
- Not showing a running demo.
- Fallback output presented as if it were Gemma 4.
- No public GitHub repository.
- No video or weak video.
- No clear explanation of why the project needs Gemma 4.
- No safety discussion.

## What would increase the score fastest

1. Record the app using real local Gemma 4 via Ollama.
2. Put the GitHub README screenshots at the top.
3. Add the 3-minute YouTube video link in the Kaggle writeup.
4. Submit under Global Resilience and mention Safety & Trust/Ollama fit.
5. Use the phrase: "model proposes, deterministic tool routes, human verifies".
